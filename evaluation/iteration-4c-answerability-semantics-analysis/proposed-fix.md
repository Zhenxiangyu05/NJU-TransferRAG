# Answerability Iteration 4C 最小修正方案

## 1. 目标

继续保留 4B 的总体架构、Java 确定性聚合、`temperature=0`、`TECHNICAL_ERROR`、Source Pruning 和 fail-closed 策略。只收窄 aspect 语义与 `AMBIGUOUS` 触发条件，不重新设计 Answerability 架构。

本文件仅提出方案，不实现任何代码修改。

## 2. 修正一：Aspect 必须锚定用户原问题

在 checker 指令中增加窄规则：

- 每个 aspect 必须对应用户问题中的一个明确语义片段。
- 不得增加用户未要求的实施步骤、时间分配方案、深层原因、附加条件或完整性要求。
- “如何平衡/有什么建议”询问的是资料明确给出的原则、取舍和建议；只要 Evidence 直接给出这些内容，不得额外要求量化时间表或操作流程。
- “为什么”只要求资料明确给出的原因和解释层级；不得自行要求更深层的因果机制。

可在最小结构化输出中增加 `questionAnchor`，要求复制对应的原问题短语。Java 只检查该字段非空且确实来自问题文本，用于防止完全脱离问题的 aspect；不让 Java 承担复杂语义理解。

预期作用：

- `TRAG-060`：禁止把“平衡建议”升级成“具体时间分配方案/操作步骤”。
- `TRAG-066`：禁止把“学院重视数理能力”继续升级成更深层原因。
- 三个 negative guard 不受影响，因为日期、数字和未覆盖子问题本来就在问题中明确出现。

## 3. 修正二：证据按问题要求的抽象层级判断

增加一条 Evidence Coverage 规则：若 Evidence 对用户询问的事实作出直接陈述或近义表述，即可判 supported；不能因为资料没有给出比问题更细的说明而判 false。

对经验建议类，下面的证据已经足够回答 `TRAG-060`：

- 微积分II需要大量投入；
- 过度投入导致离散、高程、计算系统准备不足；
- 应平衡微积分与转计笔试机试内容的时间。

它不需要额外提供每周小时数或分阶段行动计划。

## 4. 修正三：收窄年份适用性要求

对 `TRAG-008`，问题中的“2026年”是查询适用范围，不应自动拆成独立的“正文必须逐字再次证明2026”要求。

最小规则建议：

- 当 Source 的 `effectiveYear` 与问题年份一致，且资料上下文是该年度指南时，可用该 metadata 建立时间适用性。
- 正文提到某种形式“自2025年变为……”表示变化起点，不应自动理解为“仅适用于2025年”。
- 只有正文明确限定“仅2025年”、明确说明2026已变化，或不同年度证据互相冲突时，才判年份不充分或歧义。

该规则只改变时间证据的解释，不降低对日期、时间、成绩和课程等精确事实的要求。

风险：若 `effectiveYear` metadata 错误，可能把旧规则误当现行规则。因此实现时必须限定为 metadata 与文档年度上下文一致，且正文不存在明确反证；不能把任意历史文字都视为当前政策。

## 5. 修正四：列表问题只检查用户要求的列表

对于“初试和复试形式是什么”，核心内容仅为：

- 初试形式：闭卷笔试、2小时、100分；
- 复试形式：面试10分钟，其中陈述2分钟、提问8分钟。

不得增加选拔人数、录取标准、成绩权重等 aspect。若 Evidence 使用清晰标题或结构完整列出这些内容，不能因为理论上可能还有其他细节而判不完整。“包括但不限于”仍保持原有 fail-closed 规则。

预期作用：配合年份适用性收窄，修复 `TRAG-008`；不会使 `TRAG-003/031/062` 通过，因为它们的完整关键事实仍不在生产 Top3。

## 6. 修正五：AMBIGUOUS 必须证明核心冲突

保留 `ambiguity` 语义，但要求 checker 同时输出一个最小冲突说明，例如：

```json
{
  "conflicts": [
    {
      "aspect": "用户明确询问的核心事实点",
      "citationIds": ["S1", "S2"],
      "alternativeValues": ["规则A", "规则B"],
      "missingDiscriminator": "cohortYear"
    }
  ]
}
```

Java 只有在以下条件全部成立时才聚合为 `AMBIGUOUS`：

1. `conflicts` 非空；
2. aspect 有有效 `questionAnchor`；
3. 至少两个合法 citationId；
4. `alternativeValues` 至少有两个不同非空值；
5. 用户问题确实缺少 `missingDiscriminator`。

若差异不属于核心 aspect，继续按正常 Evidence Coverage 判断。若用户只要求举例且共同部分足够完整回答，则不触发歧义；若用户要求完整列表而列表不同，则继续澄清。

## 8. Negative Guards 风险

总体风险为低到中等，可通过保持以下边界控制：

- 精确日期、时间、数字仍必须直接出现，`ARAG-N01/N02` 应继续拒答。
- 多子问题仍做必须 aspect 的 AND 汇总，`ARAG-N03` 缺考试具体时间时仍拒答。
- “按问题抽象层级判断”仅禁止增加要求，不允许用主题相关内容替代直接证据。
- 年份 metadata 只能在与文档年度上下文一致且正文无反证时使用。
- 列表完整性放宽只适用于 Evidence 明确呈现完整结构的情况，“包括但不限于”仍判不足。

最大的风险是年份适用性规则误用和经验类“建议”判断过松。后续若实现 4C，应首先运行定向单元测试与 `answerability-regression-cases.json`，重点确认三个 negative guard、现有 PASS guards 和 `TRAG-023/025/027/029` 的歧义行为。
